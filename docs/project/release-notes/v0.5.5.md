# Mercator v0.5.5

The operator console no longer bricks on booking decisions written before
candidates carried a `disposition`. Durable history holds such events — the
v0.5.4 migrations repair Booking identity but deliberately do not invent
candidate dispositions — and the console's decode treated the missing key as
a non-retryable feed error, blanking the whole Workspace canvas for any
workspace whose replay contained one.

The console now decodes `disposition` as optional wherever a stored decision
is rendered (the Workspace feed and the run Decision panel both replay
history) and shows "unrecorded" for candidates that predate the field.
History is displayed as it was written, not rewritten.
